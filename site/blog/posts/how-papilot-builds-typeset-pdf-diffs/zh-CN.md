让编程智能体帮你收紧两页数学证明，或是统一整篇 LaTeX 论文里的记号，往往几秒钟就能拿到一份 `git diff`。真正消耗心力的时候，反而是从打开这份代码补丁开始的：改一个自定义宏、重排一段英文换行，或者微调一组 `\begin{aligned}` 公式，都会在屏幕上铺开几十行红绿交错的反斜杠。就算对整个项目跑一遍 `latexdiff`，复杂的数学环境与图表宏也常常报错、把后文的分页全部挤乱，更无法让你优雅地“接受第二段、拒绝第四个公式”，再把选定的修改干净地写回 `.tex` 源文件。

[Papilot](https://github.com/PapilotAI/papilot) 想把编译后的 PDF 变成真正的主工作区，排版级对比就绝不能像流水线末端的批处理导出那样迟缓。智能体的每一轮修改都必须与原稿工作目录安全隔离，编译耗时要接近本地单次增量 `latexmk`，页面高亮要精准归属到每一条批注，而且每一次“接受”或“拒绝”都必须可撤销、可追溯。下面分享这套审阅流水线在底层是如何运转的。

## 用 Git 工作树与增量快照隔离每一次智能体修改

在速度之前，首先是原稿的安全边界。当你在 PDF 页面上高亮句子或框出公式，把批注发给 Codex、Claude、Cursor 或内置的 Papilot Writer 时，智能体永远不会直接改动你正在阅读的主工作目录，而是在专属于当前任务的独立 Git 工作树（worktree）中编辑源码。

为了保证新旧版本对比严格可复现——并且让点击跳转所依赖的 SyncTeX 始终指向当前展示的那一版源码——每一次构建都必须在各自独立的不可变目录中完成，而不能在原文件夹里原地覆盖。如果面对一部几百页的学位论文，每次构建都让 Git 全量扫描哈希整个仓库，仅准备快照就会拖慢节奏。为此，Papilot 使用独立的私有 Git 快照索引（主工作区为 `.git/papilot/working-index`，任务工作树内为 `papilot/snapshot-index`）记录快照：每次以前一版快照或仓库现有索引为起点，Git 只需重新哈希文件大小或修改时间真正发生变化的源文件。

![四阶段工程流水线示意图：Git 工作树快照、基于种子状态的章节增量编译、排版级差异归属，以及可撤销审阅日志。](/assets/blog/review-pipeline.zh-CN.svg "每轮智能体任务都在独立 Git 工作树中运行，复用热缓存并行编译改动章节，完成细粒度正文与原子数学公式对比，并在真正应用回原稿前通过审阅日志管理每项决定。")

## 让隔离的不可变 LaTeX 构建像单次增量编译一样快

在一篇多章节长文或三百多页的论文上从零运行 `pdflatex` 或 `xelatex`，往往要跑多轮才能结清交叉引用、参考文献以及 `minted` 或 TikZ 缓存。既然每次构建都在独立目录里进行，如果简单地新建空文件夹从头编译，就会把 `latexmk` 最宝贵的增量状态全部丢弃。

Papilot 通过四项机制把隔离构建的额外开销压缩到约一秒量级：

1. **克隆最接近的历史构建目录。** 准备新构建时，Papilot 会在相同章节集合的近期已完成构建中，挑选与新版本源码差异文件最少的一份作为起点。在采用 APFS 文件系统的 macOS 上，`cp -c` 写时复制（copy-on-write）能一步克隆整个构建目录，随后只从 Git 流式写入发生变动的少量文件。
2. **原地重写 SyncTeX 与保留辅助文件缓存。** `latexmk` 的依赖数据库、`.aux` 与 `.bbl` 辅助文件以及 `minted` 缓存都会随克隆一并继承。由于各个构建目录采用等长路径键名，Papilot 可以直接在保留的 SyncTeX 数据和日志里原地替换路径前缀，而不会破坏字节偏移量——这样 `latexmk` 通常只需跑一轮增量编译，输入未变时甚至无需重跑。
3. **基于种子构建的并行 `\includeonly` 章节对比。** 当智能体只修改了多文件论文中的一两章时，审阅构建不会重编整本书，而是以完整基础构建（seed）的 `.aux` 辅助文件为底座，利用 `\includeonly` 同时并行编译修改前后的变动章节，既保住了跨章引用与图表编号的准确性，又固定了统一构建日期，避免跨午夜时 `\today` 制造虚假差异。
4. **首轮预览上屏与脏缓存自动回退。** 当某次修改移动了页码或引用、`latexmk` 需要继续跑后续轮次时，钩子会在第一轮 TeX 编译结束后立即把新生成的页面与 SyncTeX 数据呈现在视图中，让后续结清编号的轮次在后台完成；一旦旧辅助文件引发报错，系统会自动回退到干净目录重试一次。

| 构建与审阅环节 | 传统全量重建或脚本拼接方案 | Papilot 增量审阅流水线 |
| --- | --- | --- |
| 工作区隔离方式 | 直接改动原目录，或每次全量拷贝所有项目文件 | 任务级独立 Git 工作树 + 私有 Git 增量快照索引（`working-index` / `snapshot-index`），APFS 下通过 `cp -c` 克隆 |
| 多章节论文审阅编译 | 修改前后分别从头跑多轮整书编译 | 继承种子构建 `.aux` 状态，对变动章节并行执行 `\includeonly` 增量构建并锁定日期 |
| SyncTeX 与辅助缓存 | 新目录每次从零生成 | 等长构建目录键名支持原地重写 SyncTeX 路径，跨天保留 `latexmk` 缓存 |
| 多轮编译等待体验 | 必须等 BibTeX 与全部交叉引用轮次彻底跑完才出图 | 首轮编译完成即刻刷新页面预览，后续轮次在后台收敛页码与引用编号 |

## 细粒度正文偏移映射与原子级公式对比

拿到修改前后的两份编译版面后，仅仅把两整页 PDF 左右并排放着依然不够直观——作者希望在论文原有的行距与上下文里，逐条对每一处逻辑修改拍板。

Papilot 在差异归属上区分了“**可拆分的散文**”与“**必须保持完整的排版结构**”：

- **正文细粒度源码偏移。** 在普通正文段落里，每一处增删都精确映射到底层 `.tex` 文件的字符偏移区间，并在渲染后的 PDF 上生成各自独立的高亮标记；源码里单纯的空格或换行重排会自动并入同段最近的实质性修改中，避免审阅时被无意义的排版微调打扰。
- **复杂数学与图表的原子保护。** 行间公式、表格、插图与参考文献条目保持为不可拆碎的原子单元；页面上相邻重叠的裁剪区域会合并为同一块带上下文的版面对比条，完整保留真实的字距、换行与数学公式排版。

![Papilot 界面截图：在排版后的论文页面上框选公式并高亮句子，各自附有作者批注。](/assets/blog/notes.zh-CN.png "页面批注将引文与公式区域精确关联到源码偏移区间，使审阅抽屉可以每次只聚焦单条批注的高亮与备选方案。")

当你在发送任务时附带了 PDF 批注，Papilot 还可以在同一轮请求里让智能体一并准备简明的**单条批注备选改法**。在审阅界面打开前，系统会先校验每份候选补丁是否严格落在对应批注关联的源码区间内，并在隔离环境中预编译版面。点击某条批注即可在页面上只聚焦该处修改，在本地缓存的不同措辞方案与 `.tex` 源码视图之间即时切换——**整个审阅过程完全在本地完成，不会再触发任何额外的模型调用**。

## 在改动进入主分支之前：可撤销的审阅日志

在以源码为中心的编辑器里，点击对话侧栏的“保留”往往当场就会改写你的工作区文件。而在 Papilot 中，“审阅判断”与“落盘交付”被刻意拆成了两步。

无论是接受整处修改，还是为某条批注选定备选方案，都只是写入当前任务的可撤销审阅日志（undoable review journal）；拒绝某条批注则会通过同一套日志立即恢复对应的原始 `.tex` 片段，而不破坏同一段落里的其他决定。直到全部过目完毕，才由你决定是点击 **应用**（Apply）将通过审阅的改动写回工作目录而不自动提交（若已开启同步，改动会在约 1 秒内送达合作者的 Overleaf 页面），还是点击 **提交**（Commit）仅将本任务已接受的改动在当前分支上生成一次干净提交。

你可以直接打开浏览器里的[静态交互演示](/demo/)，免安装体验按批注聚焦的排版对比、预设任务回放与本地版本管理。Papilot 的审阅引擎、编译流水线与桌面客户端全部以 MIT 协议开源，欢迎前往 [GitHub 仓库](https://github.com/PapilotAI/papilot)阅读源码、提交 Issue，或点亮一颗 Star 支持我们的开发。
