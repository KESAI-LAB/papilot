LaTeX で論文を書くほぼすべての研究チームは、最終的にツール選びである種の妥協点に落ち着きます。数 GB もの TeX ディストリビューションを入れることなく、ブラウザを開くだけですぐ原稿を直せる環境を好む共著者もいれば、Git やショートカットキー、コーディングエージェントをつないだローカルのコードエディタに腰を据える人もいます。そしてもう一人は、コンパイル済みの PDF を書き出してタブレットや全画面リーダーで通読します——実際に組版された紙面と向き合って初めて、ぎこちない段落のつながりや窮屈な表、うっかり取り違えた添字が浮かび上がってくるからです。

今日、「AI で LaTeX を書く環境」を探す人にとって、足りないのはもはや賢い言語モデルではありません。主流のコーディングエージェントはすでに、複数ファイルにまたがるマクロ定義の追跡や `.bib` 書誌エントリの整理、さらには数式の組み替えまで難なくこなします。日々の推敲の質を本当に左右するのは、エージェントを取り巻く**作業領域の契約**です。どこで変更すべき箇所を指し示し、AI が書き換えた結果を何によって検証し、そしてより手に馴染むツールへ乗り換えたとき、共著者にも移行を強いることになるかどうか——そこに本質があります。

どれか一つのツールがすべてを置き換えると主張するよりも、現在主流となっている 3 つの LaTeX ワークフロー——Overleaf に代表されるブラウザの分割画面エディタ、コーディングエージェントと組み合わせたローカルのソース IDE、そして組版済み PDF を中心に据えた [Papilot](https://github.com/PapilotAI/papilot) の作業領域——を並べて客観的に比較し、リアルタイム同期によって同じ一本の原稿の上でどうシームレスに連携できるかを見ていきましょう。

## 既存の LaTeX ツールが解決してきたこと

「ソースコード中心」の AI 編集がどこで行き詰まるのかを見る前に、なぜ Overleaf とローカルのコードエディタが学術執筆の主流になったのかを正当に評価しておく価値があります。

**Overleaf は共同執筆の導入ハードルを解消しました。** ブラウザベースの TeX 環境が普及する前は、機関をまたいで共著者と論文を書き始めようとすると、アブストラクトを一行書く前に TeX Live の年次違いや不足している `.sty` パッケージ、Git のマージ競合を片付けるところから始まりました。リンクを一つ共有するだけで全員がブラウザから同時にタイピングし、互いのカーソルを文字単位でリアルタイムに確認できる仕組みは、異なる技術背景を持つメンバーが設定ゼロで同じ原稿に入るための最も手軽な方法であり続けています。特にローカルの TeX 環境が入っていない端末から作業するときには欠かせません。

**ローカルのソース IDE はプロジェクトの規模と自動化を解決しました。** VS Code と LaTeX Workshop、あるいは Cursor や Neovim に Claude Code、Codex などの CLI エージェントを組み合わせてローカルの Git リポジトリで作業すれば、高速な複数ファイル検索、オフラインでの `latexmk` コンパイル、再現可能な図表生成スクリプト、そして `.cls` ドキュメントクラスや `.sty` パッケージ、プログラム的な TikZ 図表を記述する際の緻密なソース制御が手に入ります。

しかし、これら二つのワークフローはまったく同じ地点で大きな摩擦に突き当たります。**本文の論証や数式の導出に対して AI が行った実質的な改訂をレビューする工程**です。

![3つの LaTeX ワークフローの並列比較：Overleaf のブラウザ分割画面、コーディングエージェントを備えたローカルのソース IDE、そして Overleaf リアルタイム同期に対応する Papilot の PDF 中心ワークスペース。](/assets/blog/three-workflows.ja.svg "Overleaf は環境構築不要のブラウザ共同編集に、ソース IDE は生のマークアップ編集に最適化されています。Papilot は AI への注釈と改訂レビューを組版済み PDF に集約し、リアルタイム同期で Overleaf とつながります。")

ブラウザの分割画面でもコード IDE でも、AI アシスタントが書き換えるのは `.tex` ソースであり、著者に差し出されるのもまずは赤と緑が入り乱れるコードの diff です。行折り返しをまたいで組み替えられた英文の段落や、プロジェクト独自マクロを含む複数行の `\begin{align}` 導出を前にしてコードパッチを読むということは、頭の中で LaTeX を「脳内コンパイル」することを意味します。たとえ PDF 全体を再コンパイルしたとしても、9 ページ目のどの記号が微修正されたのかを PDF 側が教えてくれるわけではなく、結局は新旧二つの版を目視で見比べるしかありません。

## 6 つの観点で見るワークフローの客観比較

以下の表は、日々の執筆、AI への指示、変更の検証、そして共同執筆において、3 つの環境がどのように異なるかを整理したものです。

| 比較の観点 | Overleaf（ブラウザエディタ） | ローカルのソース IDE + コーディングエージェント（VS Code / Cursor / CLI） | Papilot（組版済み PDF 中心のエージェント作業領域） |
| --- | --- | --- | --- |
| 主作業領域の重心 | 左右分割画面：左に `.tex` エディタ、右に PDF プレビュー | `.tex` のファイルツリーとコードペインが中心で、PDF は補助的なプレビュータブ | コンパイル済みの PDF 原稿そのものが作業台（必要に応じていつでもソースを表示可能） |
| AI への修正指示の伝え方 | コード断片をチャット欄にコピーするか、`.tex` バッファ内で指示 | ファイルパスや行範囲、選択した `.tex` コードを指定してエージェントに送信 | PDF ページ上で文をハイライト、または数式・図表を枠で囲んで注釈を記入し、SyncTeX が正確なソース行を対応付け |
| AI による変更のレビュー | 生の `.tex` の変更箇所を見るか、再コンパイルして新しい PDF 全体を目視で探す | 生の LaTeX マークアップに対する行単位の赤緑 `git diff` | ページ上のその場で組版済みの変更前後 PDF 差分を表示（注釈ごとの代替案やソース表示の切り替えに対応） |
| 共著者との共同作業 | プロジェクトリンクや共有リンクによるブラウザ上のネイティブなリアルタイム共同編集 | Git の push / pull に依存し、Overleaf 派の共著者とは分断されやすい | 内蔵 Git ワークツリーによるタスク隔離に加え、**Overleaf との約 1 秒の双方向リアルタイム同期**に対応 |
| AI モデル・エージェントの選択 | プラットフォーム組み込みのアシスタント選択肢に固定 | 特定の IDE ベンダー、または設定した単一の CLI ツールに紐づく | 自身のログインや API キーで全 16 種類のエージェントを利用可能（内蔵 Papilot Writer と Codex、Claude、Cursor、Copilot、Antigravity、Pi、OpenCode など 15 種の外部エージェント） |
| 動作環境・ファイル・ライセンス | クラウドホスト型プロジェクト（ローカルへの TeX 導入不要） | ローカルのプレーンテキストファイル + Git + ローカル TeX ディストリビューション | ローカルのプレーンテキストファイル + Git + ローカル TeX ディストリビューション。MIT ライセンスの無料オープンソース |

## 共著者に乗り換えを強いずに協業する：Overleaf との双方向リアルタイム同期

多くの研究者がローカルの LaTeX ツールへの移行をためらう最大の理由は、機能そのものではなく、きわめて現実的な一言に尽きます。「指導教員と 3 人の共著者がすでに Overleaf で編集しているから」です。ZIP を書き出してローカルで AI に修正させ、変更した `.tex` ファイルをブラウザのタブへ貼り直せば、共著者が書き足したばかりの段落をたちまち上書きしてしまいます。

Papilot 0.11 から搭載された「**Overleaf と同期**」（Sync with Overleaf）は、このトレードオフを取り除きます。Overleaf のプロジェクトリンクや編集権限付きの共有リンクを Papilot に直接貼り付けてインポートすることも、既存のローカル原稿フォルダを対応する Overleaf プロジェクトに紐づけることも可能です。起動中は、Overleaf のリアルタイム編集サービスを通じてローカルファイルとリモートプロジェクトが常に足並みを揃えます。

- **約 1 秒での双方向反映。** Papilot でレビューして承認・適用した変更は約 1 秒で共著者の Overleaf ブラウザタブに届き、共著者が Overleaf 上で入力した編集もリアルタイムでローカルの `.tex` ファイルとコンパイル済み PDF に反映されます。
- **同じ段落での文字単位の同時マージ。** 双方が同じ段落を同じ瞬間に編集した場合でも、Overleaf のブラウザタブ同士と同じように文字単位でマージされ、ファイル全体が上書きされることはありません。
- **無料アカウントのまま利用でき、共有原稿を汚さない。** 有料の Overleaf Git アドオンは不要で、標準の無料アカウント（およびセルフホスト版 Overleaf インスタンス）でそのまま動作します。しかも AI エージェントの各試行はローカルの独立した Git ワークツリー内に隔離されるため、一箇所ずつ確認して「適用」をクリックするまで、未検証の下書きが共著者に送られることはありません。

![ページ上で組版済みの変更前後比較と、承認・却下・コメントの操作を表示する Papilot の製品画面イメージ。](/assets/blog/review.en.png "共有中の Overleaf プロジェクトへ変更を反映する前に、AI の提案をすべて組版済みの変更前後差分として手元のページ上で確認できます。")

原稿の取り込みも同様にスムーズです。「**インポート・開く**」パネルは arXiv の論文 URL（アブストラクト、PDF、HTML リンク）、Overleaf の閲覧・編集リンク、公開 GitHub リポジトリの URL を受け付け、メインの `.tex` エントリファイルとコンパイラエンジンを自動判別します。白紙から書き始める場合も、[Papilot Universe](https://papilot.ai/universe/) に 400 以上の国際会議をはじめ論文誌・学位論文・スライド・ポスター・履歴書・書籍向けのテンプレートが用意されており、すぐにコンパイルを始められます。

## 執筆フェーズに合わせて最適なツールを使い分ける

Papilot はディスク上の標準的な `.tex` および `.bib` プレーンテキストファイルを直接扱うため、これら 3 つのワークフローは排他的なものではなく、実際の研究生活の中で自然に補完し合います。

1. **ブラウザで Overleaf を使うとき**：TeX 環境が入っていない端末やタブレットから出先で原稿を確認するとき、借りた PC で手早く誤字や言い回しを直すとき、あるいはローカル環境を構築しない共著者を招待するときには、ブラウザ版が最も軽快です。
2. **ローカルのソース IDE を開くとき**：独自の `.cls` / `.sty` スタイルファイルをゼロから設計するとき、低レベルなマクロ展開エラーをデバッグするとき、あるいは Python や R から `.tex` の実験結果テーブルを一括生成するパイプラインを組むときには、コードエディタが最も直接的です。
3. **Papilot を主作業台に据えるとき**：本文の執筆、構成の練り直し、数式導出の検証、そして AI エージェントを用いた何巡もの推敲を行う段階では、組版された紙面を直接指し示し、提案されたすべての変更をレンダリング済みの変更前後 PDF 差分として見比べることで、学術的な判断力を研ぎ澄ませたまま、明示的に適用するまで共有原稿を安全に守れます。

ローカルの TeX 環境やモデルを設定する前に、まずはブラウザ上でそのまま動く[インタラクティブデモ](/demo/)を開き、PDF 上への注釈から組版差分の個別レビューまでの一連のループを体験してみてください。このワークフローがご自身の論文執筆にフィットしそうであれば、[papilot.ai](/ja/) から macOS・Windows・Linux 向けデスクトップアプリをダウンロードし、次の締切の前にいつでも見つけられるようぜひ [GitHub で Papilot にスターを付けてください](https://github.com/PapilotAI/papilot)。
