幾乎每個用 LaTeX 寫論文的團隊，最終都會在工具上達成某種妥協：有人喜歡打開瀏覽器就能改稿，不必折騰好幾 GB 的 TeX 發行版；有人習慣待在本機程式碼編輯器裡，搭配 Git、快捷鍵與程式設計 AI 代理；還有人總要把編譯好的 PDF 匯出來放到平板或全螢幕閱讀器裡通讀——因為只有面對真正排好版的頁面，生硬的段落銜接、擁擠的三線表與悄然寫錯的上下標才會浮出水面。

今天大家搜尋「AI 寫 LaTeX 工具」時，缺的早已不是足夠聰明的模型。主流程式設計代理已經很擅長跨檔案檢索巨集定義、整理 `.bib` 文獻，甚至重排公式。真正決定日常改稿品質的，是圍繞代理建立的**工作區契約**：你在哪裡指出問題、拿什麼核對 AI 改出來的結果，以及換用更順手的工具時，會不會迫使合作者跟著搬遷。

與其宣稱某一款工具能取代一切，不如把當前最常見的三種 LaTeX 工作流放在一起客觀對比——以 Overleaf 為代表的瀏覽器分割畫面編輯器、接入程式設計代理的本機原始碼 IDE，以及 [Papilot](https://github.com/PapilotAI/papilot) 以完稿 PDF 為中心的工作區——看看它們各自擅長什麼，又如何透過即時同步在同一篇手稿上無縫配合。

## 現有 LaTeX 工具各自做對了什麼

在討論「以原始碼為中心」的 AI 改稿瓶頸之前，值得先承認 Overleaf 與本機程式碼編輯器之所以成為主流，是因為它們切切實實解決了各自時代的痛點。

**Overleaf 解決了多人協作的入門門檻。** 在線上編輯器普及之前，跨校合作寫一篇論文，往往還沒動筆寫摘要就要先幫合作者排解 TeX Live 年份差異、缺失的 `.sty` 套件與 Git 合併衝突。傳一個連結就能在瀏覽器裡同時打字、即時看到彼此的游標，至今仍是讓不同技術背景的合作者零設定進入同一份稿件最省心的方式，尤其適合手邊沒有安裝本機 TeX 環境的裝置。

**本機原始碼 IDE 解決了專案規模與自動化。** 用 VS Code 搭配 LaTeX Workshop，或是 Cursor、Neovim 加上 Claude Code、Codex 等命令列代理，在本機 Git 儲存庫裡工作，能獲得極快的跨檔案搜尋、離線 `latexmk` 編譯、腳本化圖表產生，以及在編寫 `.cls` 文件類別、`.sty` 套件或複雜底層 TikZ 圖表時的精細原始碼控制力。

但這兩種工作流在同一個環節遇到了明顯阻力：**審閱 AI 對內文論證與數學推導所做的實質性修改**。

![三種 LaTeX 工作流並排對比：Overleaf 瀏覽器分割畫面、接入代理的本機原始碼 IDE，以及支援與 Overleaf 即時同步的 Papilot PDF 工作區。](/assets/blog/three-workflows.zh-Hant.svg "Overleaf 擅長零設定網頁多人協作，原始碼 IDE 擅長底層標記編輯；Papilot 將 AI 批註與修改審閱移回算繪後的 PDF，並透過即時同步與 Overleaf 互通。")

無論在網頁分割畫面還是程式碼 IDE 裡，AI 助手修改的都是 `.tex` 原始碼，交回給作者審閱的也首先是紅綠交錯的程式碼 diff。面對跨行重排的英文長句，或是夾雜自訂巨集的多行 `\begin{align}` 推導，看程式碼修補檔意味著作者必須在腦海裡「人肉編譯」LaTeX；哪怕重新編譯出整份新 PDF，它也不會主動標出第九頁究竟改了哪幾個符號，你依然得靠肉眼在新舊兩版之間來回比對。

## 六個維度的客觀工作流對比

下表從日常寫作、AI 批註、改動審閱到多人協作，梳理了三種環境的真實差異：

| 對比維度 | Overleaf（網頁線上編輯器） | 本機原始碼 IDE + 程式設計代理（VS Code / Cursor / CLI） | Papilot（以完稿 PDF 為中心的代理工作區） |
| --- | --- | --- | --- |
| 主工作區重心 | 左右分割畫面：左側 `.tex` 程式碼編輯，右側 PDF 預覽 | `.tex` 目錄樹與程式碼窗格為主，PDF 僅作附屬預覽分頁 | 編譯後的 PDF 手稿本身即為工作檯，需要時可隨時展開原始碼對照 |
| 向 AI 表達修改意圖 | 複製程式碼片段到對話欄，或在 `.tex` 游標處提問 | 指定檔案路徑、行號範圍或選取 `.tex` 原始碼片段交給代理 | 直接在 PDF 頁面上螢光標記句子或框選公式、圖表寫批註，SyncTeX 自動定位原始碼行 |
| 審閱 AI 的修改結果 | 檢視 `.tex` 原始碼變動，或重編譯後在整份新 PDF 中人工尋找差異 | 基於文字行的紅綠 `git diff` 原始標記語言修補檔 | 在頁面原位展示排版後的修改前後對比（含算繪好的公式與表格），支援單則批註備選方案與原始碼切換 |
| 多人協作方式 | 瀏覽器原生多人即時游標同步，分享連結即可加入 | 依賴 Git 推送與拉取；若合作者慣用 Overleaf 則容易脫節 | 內建 Git 工作樹隔離任務，**同時支援與 Overleaf 約 1 秒雙向即時同步** |
| 代理與模型選擇 | 綁定平台自身提供的內建助手選項 | 通常綁定單一 IDE 廠商，或每次手動切換單一 CLI 工具 | 自備帳號或金鑰使用全部 16 種代理：內建 Papilot Writer 與 15 種程式設計代理（Codex、Claude、Cursor、Copilot、Antigravity、Pi、OpenCode 等） |
| 執行條件、檔案與授權 | 雲端代管專案，本機免裝 TeX 環境 | 本機純文字檔案 + Git + 本機 TeX 發行版 | 本機純文字檔案 + Git + 本機 TeX 發行版；依據 MIT 授權免費開源 |

## 不必說服合作者搬遷：與 Overleaf 即時雙向同步

許多研究者對本機工具卻步，真正的原因往往不是功能，而是一句非常現實的顧慮：「我的指導教授和另外三位合作者都在 Overleaf 上改稿。」如果把專案匯出成 ZIP 在本機讓 AI 修改，再把 `.tex` 檔案貼回網頁，幾乎不可避免地會覆蓋合作者剛剛寫下的段落。

從 Papilot 0.11 開始，**與 Overleaf 同步**（Sync with Overleaf）直接消除了這道二選一的門檻。你可以貼上 Overleaf 專案連結或具編輯權限的分享連結直接匯入，也可以把既有的本機稿件資料夾連結到對應的 Overleaf 專案。執行期間，本機資料夾與遠端專案會透過 Overleaf 的即時編輯服務保持同步：

- **約 1 秒雙向送達。** 你在 Papilot 中審閱接受並套用到稿件的修改，約 1 秒內就會出現在合作者的 Overleaf 瀏覽器分頁裡；對方在網頁上的輸入也會即時寫回你的本機 `.tex` 檔案並更新 PDF。
- **同段並行逐字合併。** 當雙方恰好在同一段落同時編輯時，改動會像兩個 Overleaf 瀏覽器分頁之間那樣按字元合併，而不會整份檔案互相覆蓋。
- **一般免費帳號即可使用，且不污染共享稿件。** 同步無需開通 Overleaf 付費 Git 附加功能（同樣支援自架 Overleaf 伺服器）；而 AI 代理的每次嘗試依然隔離在本機獨立的 Git 工作樹中，在你逐處審閱並點擊「套用」之前，絕不會把未經核實的半成品直接推給合作者。

![Papilot 產品示意圖：展示論文頁面原位的修改前後排版對比，以及接受、拒絕和留言操作。](/assets/blog/review.en.png "在將改動同步給 Overleaf 上的合作者之前，先在本機頁面上逐處審閱排版後的修改前後對比。")

專案的起步同樣順暢：在「**匯入或開啟**」面板中貼上 arXiv 論文連結、Overleaf 分享連結或公開 GitHub 儲存庫網址，Papilot 會自動識別主 `.tex` 入口檔案與編譯引擎；如果是新建文稿，[Papilot Universe](https://papilot.ai/universe/) 提供了涵蓋 400 多個學術研討會以及期刊、學位論文、投影片、海報、履歷與書籍的開箱即用範本。

## 依寫作階段選擇合適的工具組合

因為 Papilot 底層操作的就是磁碟上標準的 `.tex` 與 `.bib` 純文字檔案，這三種工具在真實研究生活裡完全可以各司其職：

1. **只打開瀏覽器用 Overleaf**：當你臨時在沒有設定 TeX 環境的電腦或平板上檢視專案、隨手改幾個拼字錯誤，或是邀請不打算安裝本機環境的合作者共同編輯時，網頁端依然最輕便。
2. **切回本機原始碼 IDE**：當你正在從零編寫自訂 `.cls`/`.sty` 套件、排解底層巨集展開錯誤，或用 Python、R 腳本批次產生實驗數據表格與巨集檔案時，純程式碼編輯器最直接。
3. **以 Papilot 為主工作檯**：當你進入內文撰寫、結構重寫、公式核查與多輪改稿階段——直接在完稿 PDF 上指認問題，逐處審閱排版後的修改前後對比，讓 AI 處理繁瑣的標記語言，而把學術判斷穩穩留在自己手裡。

在設定本機環境之前，你可以直接在瀏覽器裡打開免安裝的[互動式線上展示](/demo/)，親手體驗在 PDF 上批註與逐條審閱排版差異的完整閉環。如果這套工作流契合你的寫稿習慣，歡迎前往 [papilot.ai](/zh-Hant/) 下載 macOS、Windows 或 Linux 桌面版，也歡迎在 [GitHub 上為 Papilot 按一顆 Star](https://github.com/PapilotAI/papilot)，方便下一篇截稿日前隨時取用。
